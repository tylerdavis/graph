This repo dogfoods graph in its own pull-request checks: a **docs-drift gate** (an inferred exit gate as a merge check) and two **specialized reviewers** (structured findings posted as PR comments by the plans themselves). Every piece ships in this repo — the plans in `./.graph/plans/`, the rubric tool in `./.graph/tools/`, the workflow in `.github/workflows/graph-checks.yaml` — and every PR against graph runs them.

<Tip>
  To replicate this setup in your own repository, hand the work to your coding agent.

  ```shellscript
  npx skills add tylerdavis/graph
  ```

  This installs the [/graph-github-actions-setup](https://github.com/tylerdavis/graph/blob/main/skills/graph-github-actions-setup/SKILL.md) skill (Claude Code, Cursor, Codex, and most other agents). It walks the agent through choosing checks, scaffolding `./.graph/`, generating the workflow, and wiring secrets. The rest of this page explains the pieces the skill assembles.
</Tip>

The finished shape is the headline. Each CI job is:

```yaml
jobs:
  docs-drift:
    runs-on: ubuntu-24.04
    container:
      image: ghcr.io/tylerdavis/graph:{{release_version}}      # graph + git/jq/gh baked in
      credentials:
        username: ${{ github.actor }}
        password: ${{ secrets.GITHUB_TOKEN }}
    steps:
      - uses: actions/checkout@v4
        with: { fetch-depth: 0 }                   # plans diff refs locally
      - run: graph plan run docs_drift --input base="$BASE" --input head="$HEAD"
```

No install step (the release workflow publishes the image), no shell logic (plans own it), no output parsing (exit codes and annotations are the contract). The jobs run in seconds.

## The pieces

**Ephemeral storage.** `GRAPH_STORAGE=memory` keeps runs stateless — nothing to clean up. Plans don't need the [shape cache](/tools/shape-cache) anyway: you authored the paths.

**Repo-carried setup.** graph layers `./.graph/config.toml` over the global config and loads `./.graph/{plans,tools}/`, so the repo carries everything the checks need — config (secrets as `${ENV}` references that fail loudly when missing), plans, and the rubric tool — all reviewed like any other code.

**The github tool pack.** `[tools] packs = ["github"]` enables the [bundled tools](/tools/builtins) the plans build on: `git_changed_files`, `git_diff`, `git_file`, `git_grep`, `gh_pr_meta`, `gh_pr_comment`, `gh_pr_inline_comments`, `gh_pr_ticket`.

## `docs_drift` — an inferred gate as a merge check

The repo rule, from its CLAUDE.md: behavior changes in `crates/` must update `docs/` in the same PR. As a plan, the _decision_ — "is this diff a behavioral change?" — is one judged yes/no call, and everything around it is deterministic and free:

```yaml
steps:
  - id: E0
    tool_name: builtin__git_changed_files
    input: { base: "{{input.base}}", head: "{{input.head}}", prefix: "crates/" }
  - id: E1
    tool_name: exit
    input:
      when: { value: "{{E0.count}}", op: eq, to: 0 }
      status: success
      message: no crate code changed — docs gate not applicable
      output: { docs_required: false, reason: no_crate_changes }
  - id: E2
    tool_name: builtin__git_changed_files
    input: { base: "{{input.base}}", head: "{{input.head}}", prefix: "docs/" }
  - id: E3
    tool_name: exit
    input:
      when: { value: "{{E2.count}}", op: gt, to: 0 }
      status: success
      message: docs updated alongside crate changes
      output: { docs_required: false, reason: docs_touched }
  - id: E4
    tool_name: builtin__git_diff
    input: { base: "{{input.base}}", head: "{{input.head}}",
             paths: "crates/", exclude: "", max_bytes: 150000 }
  - id: E5
    tool_name: exit
    input:
      infer: |
        Does this diff change user-visible behavior of the graph CLI …
        Pure refactors, comment-only changes, test-only changes, and
        internal renames do not count. Answer yes only if the behavior a
        user or plan author observes would change.

        {{E4.text}}
      status: error
      message: >-
        behavioral change without a docs/ update — CLAUDE.md requires docs
        land in the same PR as the behavior change
output:
  docs_required: false
  reason: "{{E5.reason}}"
```

**Lessons:**

- **Short-circuit before you infer.** E1 and E3 are `when` gates over [github pack](/tools/builtins) tool output — a docs-only PR exits success in milliseconds with zero LLM calls. The `infer` gate is the last resort, and it sees only the truncated `crates/` diff. Worst case per PR: one judge call on the cheap `judge` role.
- **The gate is the CI contract.** `status: error` maps to process exit code 4 — distinct from exit 1 (the plan itself broke). The job needs no branching: exit 4 fails the step, and under `GRAPH_EVENTS=github` graph prints the gate's message as a `::error::` annotation itself.
- **Every exit path emits the same shape.** Both success gates and the fall-through `output` produce `{docs_required, reason}` — callers parse one contract. On a non-fired infer gate, `{{E5.reason}}` carries the judge's reasoning into the output for free (the judge explains _why_ no docs are needed).
- **Ask the judge a falsifiable question.** The prompt defines what does _not_ count (refactors, test-only changes). The judge role answers "yes only when the data clearly supports it", so the framing sets the false-positive rate. Live calibration: it flagged a commit adding an env var and a JSON field ("observable by users and plan authors"), and passed a dead-code removal with its reasoning in `reason`.

## `pr_review` — a self-contained reviewer

The plan fetches its own context, reviews, anchors findings as inline diff comments, and posts its own summary comment linking to them. The CI step is `graph plan run pr_review --input pr="$PR"` — nothing else:

```yaml
steps:
  - id: E0
    tool_name: builtin__gh_pr_meta
    input: { pr: "{{input.pr}}" }
  - id: E1
    tool_name: builtin__git_changed_files    # complete file list, never truncated
    input: { base: "{{E0.base_sha}}", head: "{{E0.head_sha}}", prefix: "" }
  - id: E2
    tool_name: builtin__git_diff
    input: { base: "{{E0.base_sha}}", head: "{{E0.head_sha}}",
             paths: ".", exclude: "Cargo.lock CHANGELOG.md", max_bytes: 300000 }
  - id: E2X
    tool_name: exit
    input:
      when: { value: "{{E2.text}}", op: empty }
      status: success
      message: empty diff — nothing to review
  - id: E3
    tool_name: user__review_graph_pr      # repo-local prompt tool: the rubric
    input: { title: "{{E0.title}}", body: "{{E0.body}}",
             files: "{{E1.files}}", diff: "{{E2.text}}" }
  - id: E4
    tool_name: user__findings_to_review_comments   # repo-local jq transform
    input: { findings: "{{E3.findings}}" }
  - id: E5
    tool_name: builtin__gh_pr_inline_comments
    input:
      pr: "{{input.pr}}"
      head_sha: "{{E0.head_sha}}"
      marker: "graph:pr_review"
      comments: "{{E4.comments}}"
  - id: E6
    tool_name: builtin__gh_pr_comment
    input:
      pr: "{{input.pr}}"
      marker: "graph:pr_review:summary"
      body: |
        Graph PR review — managed by [`pr_review.yaml`](https://github.com/tylerdavis/graph/blob/main/.graph/plans/pr_review.yaml)

        {{^E5.comments}}
        No issues found.
        {{/E5.comments}}
        {{#E5.comments}}{{#@first}}
        {{E3.summary}}

        | Severity | Invariant | File | Finding | Fix |
        |---|---|---|---|---|
        {{/@first}}| {{severity}} | `{{invariant}}` | {{#url}}[`{{file}}`]({{url}}){{/url}}{{^url}}`{{file}}`{{/url}} | {{finding}} | {{suggestion}} |
        {{/E5.comments}}
```

**Lessons:**

- **The rubric is the product.** `review_graph_pr` is a repo-local [prompt tool](/tools/user-defined#prompt--an-llm-call-as-a-tool) whose prompt enumerates _this repo's_ invariants and instructs "empty findings when clean". A focused reviewer beats a generic one precisely because it refuses to comment on everything else. It has caught real bugs in this repo's own PRs — including one in the PR that changed the reviewer itself.
- **Presentation is a template, not code.** The comment body renders with [sections](/plans/template-language#sections): iteration builds the findings table, `{{#@first}}` emits the header once, the inverted section handles the clean case. Logic stays in steps; the markdown is pure presentation.
- **Declare the output schema — it's enforced.** `review_graph_pr` declares `{summary, findings[]}` required. Models occasionally omit required fields even under provider-forced structured output; graph validates prompt-tool results against the declared `output_schema` and runs one `repair`-role fix-up, so `{{E3.summary}}` can never be a missing key at render time.
- **Review the whole diff.** The diff is scoped to nothing (`paths: "."`) minus generated files — an early version reviewed only `crates/` and `docs/`, which blinded it to the highest-leverage changes in an infra PR: workflows, plans, and the exec tools they run.
- **Ground absence claims in the complete file list, never the diff.** The diff is byte-capped and git orders hunks by path, so on a big PR the `docs/` hunks are exactly what falls off the end — an early version reported "docs not updated" false positives on a PR whose docs edits sat past the truncation point. The fix is layered: `git_changed_files` (E1) feeds the reviewer a complete, never-truncated file list; the rubric judges docs-parity and test-parity only from that list; `git_diff` appends a visible `[diff truncated: …]` marker when it cuts; and the prompt bans "not shown in the diff" as evidence — a finding must cite something the reviewer can actually see.
- **Findings flow through the pipeline, enriched at each step.** The jq transform (E4) adds `path`/`body` to each finding without dropping the original fields; `gh_pr_inline_comments` (E5) passes those extras through and adds `url` where a comment posted. So the summary table (E6) renders from one array — severity and finding from the review, the link from the post — with no join logic, which the [template dialect](/plans/template-language) couldn't express anyway. Findings the LLM couldn't pin to a line (or whose line the API rejects) simply come back without `url`, and the inverted section renders them as plain text.
- **Repeated runs refresh everything in place.** Both posting tools take a distinct `marker`, embed it as a hidden tag, and find-and-edit (or delete-then-repost) the comment carrying it. Each push updates the review instead of stacking. The marker on the summary is not optional here: without one `gh_pr_comment` falls back to `--edit-last`, which keys on the token identity — and since `graph_review_9000` posts its own summary to the same PR as the same **github-actions\[bot\]** identity, a markerless upsert would overwrite whichever summary landed most recently. One marker per plan per comment surface is the rule whenever plans share a PR.
- **Inline comments stay advisory.** They post as plain review comments, not a `REQUEST_CHANGES` review — they only gate merging on repos with _Require conversation resolution before merging_ enabled.

## `graph_review_9000` — the eight-pass reviewer

`pr_review` is one rubric'd call over the diff. `graph_review_9000` is the deeper variant: it fetches the **full contents of every changed file** at the head sha (a `map` over `git_changed_files` output at `concurrency: 8`, so the reviewer sees surrounding code rather than bare hunks), then runs one structured `builtin__infer` call carrying eight named passes — stated intent vs. diff, pipeline/control-step invariants, template & shape engine, Rust/async/storage footguns, plan composition & model routing, test coverage, repo conventions & docs parity, and CLI surface & copy.

What it demonstrates beyond `pr_review`:

- **The rubric lives in the plan, not a repo-local tool.** `builtin__infer` takes both the instruction and a `caller_output_schema`, so the whole reviewer is one plan file with no `./.graph/tools/` dependency — the schema declares `passes` (exactly eight, `minItems`/`maxItems`) and a flat `findings` array, and graph validates the model's output against it with a `repair`-role fix-up.
- **Presentation stays in templates.** `builtin__reshape` (E6) projects each finding into a GitHub alert-style comment body — no jq tool needed — and the summary comment renders the at-a-glance pass table and the collapsible sections with plain [sections](/plans/template-language#sections).
- **Ordering is asked for, not computed.** The template dialect can't sort, so the schema asks the model for `blocker_ordinal` and a severity-ordered `passes` array, and the templates iterate in the order they arrive. Logic belongs in steps or the schema — never the markdown.
- **Self-refutation before output.** The instruction ends with a gate telling the model to try to disprove each blocker against the diff and demote what doesn't survive, and to use `unverified` rather than `pass` for anything it couldn't check — a false clear costs as much as a false blocker.

It needs the **v0.9.0 image or newer**: `builtin__git_file` and `builtin__reshape` do not exist in v0.7.0.

## The workflow

The full file is `.github/workflows/graph-checks.yaml`; the notable choices:

- **The release image is the runtime.** `container: ghcr.io/tylerdavis/graph:vX.Y.Z` carries graph plus `git`, `jq`, and `gh` (pinned from official releases — distro packages lag the JSON fields and flags the pack tools use) and the `safe.directory` git config that Actions' foreign-owned workspace mounts require. The image tag is the version pin; `packages: read` plus `GITHUB_TOKEN` credentials pull it while private.
- **`GRAPH_EVENTS=github`** makes a failing plan annotate the run itself — the one sanctioned case of graph writing non-deliverable output to stdout, failure-paths only ([details](/reference/scripting-contract#streams)).
- **Guards are cheap and layered**: drafts skipped, fork PRs skipped (they have no `ANTHROPIC_API_KEY`, and the `${VAR}` reference in the repo config fails loudly as the backstop), one concurrency group per PR with cancel-in-progress.
- **Cost per PR**: worst case one `judge`-role call (docs-drift) plus two review calls — `pr_review`'s focused pass and `graph_review_9000`'s eight-pass one, the latter carrying full file contents and so the more expensive of the two; docs-only PRs pay only the reviews; drafts pay nothing.
- **One job per plan, no `needs` between them.** The three jobs are independent and run in parallel; only docs-drift can fail the check (exit 4). The reviewers always exit 0 — their comments are the deliverable, not a gate.

Want the reviewer to comment under its own name and avatar instead of **github-actions\[bot\]**? That's a token swap — see [A custom bot identity](/cookbook/bot-identity).
