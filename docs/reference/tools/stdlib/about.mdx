Standard library tools are [user-tool-format](/tools/user-defined) YAML documents compiled into the graph binary and served under the `builtin__` namespace. They're packaged and enabled as packs:

```toml
[tools]
packs = ["github", "slack"]
```

The `llm` and `data` packs are always on — no config needed. Unknown pack names fail at startup, not at plan time. To customize a built-in, put a tool file with the same `name` in the `builtin/` subdirectory of a tools directory, for example `./.graph/tools/builtin/reshape.yaml`. It replaces `builtin__reshape`, so every plan and agent that calls it picks up your version. A file directly in the tools directory is always a `user__` tool, even when its name matches a built-in. `graph tools show builtin__<name>` prints the definition in effect and its source. A file under `builtin/` must name a tool from an enabled pack, or the catalog fails to load and names the file.

## Runtime requirements

Built-ins are mostly `exec` tools: they shell out and inherit the process environment. Some packs have additional runtime requires that can be found in their respective reference pages.
